# Codebase map

A route is a web address. A feature owns a user task. A service is server code performing an operation. Start
from the visible page and follow its imports. `@/` means `src/`, as configured in `tsconfig.json`.

## Folder guide

| Folder                | Contents and ownership boundary                                                                                 |
| --------------------- | --------------------------------------------------------------------------------------------------------------- |
| `src/app`             | Next.js pages, shared layouts, and API route handlers. See its README for filename rules.                       |
| `src/features`        | Feature-specific UI, local content, types, and form helpers. It does not replace server access checks.          |
| `src/components`      | Shared layout, presentation widgets, and browser behavior providers.                                            |
| `src/config`          | Shared navigation, asset paths, and password length policy.                                                     |
| `src/server`          | Authentication, HTTP guards/errors, services, public reads, database/Redis access.                              |
| `src/generated`       | Generated Prisma Client. Regenerate it; do not edit it. It is not committed.                                    |
| `prisma`              | Database model definitions and ordered SQL migrations.                                                          |
| `public`              | Files served by path, including fonts and `/assets/` images.                                                    |
| `scripts`             | Developer startup, provisioning, imports, maintenance, and integration checks. Read a script before running it. |
| `tests`               | Focused checks using Node's built-in test runner.                                                               |
| `docs`                | Onboarding, reference guides, reviewed content sources, and historical test/design notes.                       |
| `.private`            | Ignored local credentials, logs, and verification artifacts. Never commit it.                                   |
| `.next` and `.next-*` | Build or preview output generated by Next.js. These are not source modules.                                     |

## Ask for review before touching these

| Area                                                   | Why it is risky                                                                                        |
| ------------------------------------------------------ | ------------------------------------------------------------------------------------------------------ |
| `src/server/auth`                                      | Session expiry, passwords, role checks, and CSRF protection are easy to weaken unintentionally.        |
| `src/server/redis`                                     | Connection failure must not allow access with an unvalidated session.                                  |
| `prisma/migrations`                                    | Existing databases depend on migration history. Editing an applied migration can break later installs. |
| `src/server/audit`                                     | Audit records must remain retained and protected from normal application edits.                        |
| Faculty revisions and `src/server/faculty/editor.ts`   | Drafts, published snapshots, version checks, and media cleanup interact.                               |
| Local media handlers                                   | Filesystem paths, ownership, development-only access, and file limits form a security boundary.        |
| `scripts/restrict-database.ts`, import/publish scripts | These can change users, permissions, or persisted content. They are not first-day setup commands.      |

An owner here means the code responsible for a task. Named human maintainers and review assignments must be
supplied by the team; this repository does not define them.
