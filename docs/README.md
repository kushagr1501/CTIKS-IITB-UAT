# Project guides and historical records

The first-day guides describe current behavior. Historical reports and reviewed content preserve their
original context.

Tool terms: [glossary](GLOSSARY.md).

## Open these first

| Path in this folder  | Role                                        |
| -------------------- | ------------------------------------------- |
| `GETTING_STARTED.md` | First-day setup and troubleshooting.        |
| `ARCHITECTURE.md`    | Request flow and a real edit trace.         |
| `ENVIRONMENT.md`     | Settings and safe examples.                 |
| `TESTING.md`         | Which checks to run and what they prove.    |
| `testing`            | Verification records and known findings.    |
| `content`            | Collected/reviewed faculty source material. |

## Connections and gotchas

Do not treat an old screenshot, test count, or source import as the current implementation. Verify the code
before updating a guide. Never copy live credentials into documentation.

These notes describe code responsibility. Ask your mentor for the human reviewer assigned to this area; the
repository does not name one.
